# 🤝 Руководство для участников

## 🚀 Начало работы

### 1. Форкните и клонируйте репозиторий

```bash
git clone <your-fork-url>
cd project_llm_cl
```

### 2. Создайте ветку для своей задачи

```bash
git checkout -b feature/your-feature-name
# или
git checkout -b fix/bug-description
```

### 3. Настройте окружение

```bash
python -m venv venv
source venv/bin/activate  # Linux/Mac
venv\Scripts\activate     # Windows

pip install -r requirements.txt
```

### 4. Настройте .env

Скопируйте `.env.example` в `.env` и добавьте свои API ключи.

## 🔄 Workflow

### 1. Перед началом работы

```bash
git checkout main
git pull origin main
git checkout -b feature/your-feature
```

### 2. Во время разработки

- Делайте частые коммиты с понятными сообщениями
- Тестируйте свои изменения локально
- Следуйте стилю кода проекта

### 3. Перед отправкой PR

```bash
# Убедитесь, что код работает
streamlit run main.py

# Проверьте форматирование (если используете)
# black .
# flake8 .

# Закоммитьте изменения
git add .
git commit -m "feat: описание изменений"
git push origin feature/your-feature
```

### 4. Создание Pull Request

- Опишите, что вы изменили и почему
- Добавьте скриншоты для UI изменений
- Укажите связанные Issues
- Дождитесь ревью

## 📝 Стиль коммитов

Используйте conventional commits:

- `feat:` - новая функциональность
- `fix:` - исправление бага
- `docs:` - изменения в документации
- `style:` - форматирование кода
- `refactor:` - рефакторинг без изменения функциональности
- `test:` - добавление тестов
- `chore:` - обновление зависимостей, конфигурации

Примеры:
```
feat: добавить интеграцию с API Леруа Мерлен
fix: исправить ошибку парсинга JSON в shopping_agent
docs: обновить README с примерами использования
refactor: вынести промпты в отдельный файл
```

## 🧪 Тестирование

Перед отправкой PR убедитесь, что:

1. ✅ Приложение запускается без ошибок
2. ✅ Основной flow работает (загрузка фото → диагностика → инструкция)
3. ✅ Нет ошибок в консоли
4. ✅ Изменения не ломают существующую функциональность

## 🐛 Сообщение об ошибках

При создании Issue укажите:

1. **Описание проблемы** - что не работает
2. **Шаги для воспроизведения** - как повторить ошибку
3. **Ожидаемое поведение** - что должно было произойти
4. **Фактическое поведение** - что произошло на самом деле
5. **Окружение** - OS, Python версия, провайдер LLM
6. **Скриншоты/логи** - если применимо

## 💡 Предложение новых функций

При создании Feature Request укажите:

1. **Описание функции** - что вы хотите добавить
2. **Зачем это нужно** - какую проблему решает
3. **Как это должно работать** - описание UX
4. **Альтернативы** - рассматривали ли другие варианты
